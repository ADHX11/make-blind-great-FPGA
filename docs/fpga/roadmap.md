# AFC03 开发顺序与验收

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| 0 当前框架 | Windows 跑 AFC03 模拟、v2 任务消息与回归 | 演示 DONE；取消/错误/迟到 OCR 等测试通过 |
| 1 双芯片点亮 | RK 厂家 ARM64 Linux BSP；PH1A90 厂家点灯工程 | 记录板卡版本、BSP/驱动/安路工具版本；两侧独立运行 |
| 2 RK 本地 OCR | USB 摄像头 → PP-OCR 检测/识别；加入短录音 | 板上中英文样本、NPU 推理证据、峰值内存/耗时；先单页单栏 |
| 3 文字到 PL | 实际板间桥接、任务/握手、UTF-8 校验、英文点阵缓存 | RK 仅传原文，PL 点阵与参考一致；取消/掉线不误接新任务 |
| 4 AMS 上 PL | 麦克风、训练一致的特征、定点算子和权重 | 5 个关键词真实识别；噪声、提示音回灌、拒识和延迟报告 |
| 5 机械控制 | 排版、回零、走纸、XY 脉冲、打点、限位 | 单轴→单点→单格→一行→整页，参数实机校准 |
| 6 中文 PL 转换 | 确定规范、语料、分词/读音/多音字/标点与混排 | 对照独立参考和人工核验语料；明确词表/规则范围 |
| 7 PL 视觉扩展 | 相机接入 PH1A90、预处理、DMA/帧传输 | 与软件图像对照；吞吐、时延、资源与 OCR 精度变化 |
| 8 独立展示 | 板载 OCR + PL KWS/盲文/控制 | 断开开发电脑，真实语音与书页输入，打印纸面结果 |

初期采用英文短行减少联调变量；中文依旧是目标，不把“服务能传 UTF-8”当作完成中文盲文翻译。中文先固定采用的盲文规范，再建立词语/读音/消歧与编码实现，不能用英文表编码拼音冒充中文盲文。

下一项实际工作是获取 **AFC03 对应 BSP、原理图和 PH1A90 点灯/板间通信例程**，按 [Linux 部署](afc03_linux.md) 点亮。电脑继续 Windows，不需要先装双系统。AMS 模型源码/权重仍待提供，不能提前猜定它的网络结构。

全页书籍还需处理歪斜、曲面、多栏阅读顺序、标点和分页。先验证少量固定版面，再扩展；不得为让英文演示通过而静默删除 OCR 字符。

## 展示内容

- 显示真实 PL 关键词 ID、推理周期、流程状态、盲文单元数和打印进度；计数来自硬件。
- OCR 单独显示 RK NPU 用时和识别文本，不能算作安路 PL 的模型推理。
- 对照软件定点输出、RTL 仿真与板上输出，附综合资源/时序报告。
- 实际语音触发代替模拟事件；录制时标明各模块运行位置。
- 单独测量 OCR、文字传输、翻译与机械打印耗时，不以标称 TOPS 代替效果。

若报选题三，还须按 [架构中的赛题范围](architecture.md) 补齐 3 种硬件预处理、硬件压缩、高速交互及目标检测等要求。自主命题和指定题验收不要混用。
